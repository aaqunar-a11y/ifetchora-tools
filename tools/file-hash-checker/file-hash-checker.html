    What this does not prove

    A matching hash proves one thing only: the bytes of your file are identical to the bytes that were hashed when the published value was produced. That is enough to detect a corrupt, truncated, or substituted download. It is not a statement about safety.

    • A match does not make the file trustworthy. If an attacker replaced both the download and the published checksum on the same page, the values match — and the file is still malicious.
    • It does not verify a signature. If the project publishes a .sig, .asc, or minisign file, verifying that signature is strictly stronger: it establishes who produced the file, not just that the bytes are unchanged.
    • MD5 and SHA-1 are not collision-resistant. They reliably detect accidental corruption; they must not be relied on to detect deliberate tampering. Use SHA-256 unless a publisher only offers something older.
    • It cannot tell you what the file is. Two different builds (x64 vs arm64, installer vs portable) can share a file name. Only the publisher's own file names and release notes distinguish them.
    • It says nothing about your device. The tool checks the file, not whether running it is a good idea.

    Notes on how it works

    Large files

    The file is read in 4 MiB slices and the hash is updated incrementally, so a multi-gigabyte installer does not have to be held in memory all at once. Progress is shown while the bytes are being read.

    Why there is no "upload" button

    There is no server component at all. Every byte is processed by JavaScript running in this page. You can confirm this by opening your browser's network panel: no request other than the page itself is made. That also means it keeps working with the network disconnected.

    What the emptiness of a hash tells you

    Some publishers list a file that turns out to be an HTML page — usually a 404 page, a "quota exceeded" page, or a login redirect saved by a download manager. This tool reads the first bytes of your file and tells you when that has happened, because the hash comparison alone would only say "mismatch" and send you looking in the wrong place.
